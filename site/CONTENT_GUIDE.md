# Writing docs pages (for every contributor, human or agent)

Site: Astro + Starlight in `site/`. Pages live in `src/content/docs/<section>/<slug>.mdx`, URL `/<section>/<slug>/`.
Sections: start, concepts, guides, migration, reference. (The `api/` folder is generated by TypeDoc: never edit it.)
Source of truth: the library in `../src/*.ts` (read it!) and the tests in `../test/*.test.ts` (verified behaviour).
`../docs/` is the OLD 1.x VitePress site and contains wrong claims (`signal.signal`, "dispose aborts"): use it for topics only.
`../examples/*.ts` are 2.0 examples. Never document something you didn't verify in the source.

## Facts that are easy to get wrong
- `controller.signal` IS a native AbortSignal. Never write `signal.signal`.
- `abortAfter()` replaces the previous deadline; `Infinity` / -1 / `TimeSpan.infinite` cancel it; reason is a `TimeoutError` DOMException.
- `dispose()` / `using` release the timer and parent links and do NOT abort; `abort()` works afterwards; `abortAfter()` throws.
- The abortAfter timer is unref'd: a Node script that only awaits the abort exits early (top-level await: exit code 13).
- Node core APIs (fs, timers/promises, stream, events) reject with Node's AbortError and put the reason in `cause`:
  `isTimeoutError(error)` is false there, use `isTimeoutError(controller.reason)`.
- `register()` on an already-aborted signal runs the callback synchronously; later callbacks run as event listeners (errors are uncaught in Node).

## Audience and tone
Engineers writing TypeScript or Node apps that cancel work. Short, concrete, code-first. Lead with what it's for and when to use it, then code.
No marketing fluff, no "simply", no emoji in prose. English. Sentences short. Explain *why* behind defaults.
Be honest about what the platform already does (`AbortSignal.timeout`, `AbortSignal.any`). Mention the .NET equivalent where it helps.

## Code blocks
- Use ```` ```ts twoslash ```` for TypeScript examples that import `'@ylcnfrht/enhanced-abort-controller'`: they are TYPE-CHECKED at build
  time against the real source (DOM + Node types available). A type error fails the build. Declare external things you use but don't define
  (`declare function work(signal: AbortSignal): Promise<void>;`) and put scaffolding above `// ---cut---`. Top-level `await` and `using` work;
  top-level `return` does not (wrap it in a function).
- `// @errors: 2345` above the cut shows a deliberate compile error.
- Plain ```` ```ts ```` only for snippets needing packages not installed in `site/` (Express, Fastify, Vitest). ```` ```js ```` for JavaScript.

## Build
```sh
cd site && SKIP_TYPEDOC=1 SKIP_LINKS=1 ASTRO_OUT_DIR=<scratch>/dist ASTRO_CACHE_DIR=<scratch>/cache npx astro build
```
Must end with `Complete!`. The full build (`npm run build`) also generates the API pages and checks every link.
Deploy (manual): `npm run build && npx wrangler deploy`.
